# 黑盒字节码引擎移植实战指南

**以《ランス10》（兰斯10）为例：从只有字节码，到界面能点、能编队**

> 版本 1.0 · 2026-11-14 · 连载中
> 唯一案例：把 System4 / AIN v12 的《ランス10》移植到 GNU/Linux

---

## 这本书只有一个案例

市面上讲虚拟机实现的书写的是"如何造一个 VM"。这本书写的是另一件事：

**你手上有成品游戏的字节码，没有源码，要让它在新平台上跑起来。**

全书从头到尾只讲一个项目——兰斯10 的 Linux 移植。出现的每一个函数名、每一个部件号、
每一段日志，都是这个项目里真实跑出来的：

```
[dgm] MISS dg_no=1087 page=79058 idx=1 nr=3 obj0=78950 seq=546734 now=546734
[icast] fail to=1066 src=78942 kind=struct idx=1066 ip=0x3F366C fno=25744
[inp] GetClickNumber #273 -> 1000001769
```

**不追求通用性。** 抽象成"某个引擎的某个类型"会让判据失去锋利度——你没法照着去
`grep` 自己项目里的东西。具体到函数名反而更好用：同类的引擎（Kirikiri、NScripter、
自研脚本层）结构惊人地相似，你读完自然会知道该把自己项目的哪个名字代进来。

### 为什么是兰斯10

它是这类问题的**标准样本**：

| 特征 | 兰斯10 的具体情况 |
|---|---|
| 逻辑全在字节码里 | AIN v12，约 3 万个函数、1276 个委托签名 |
| 宿主只提供"能力" | 804 个 PartsEngine 接口 + 4500+ HLL 导出项 |
| 有开源旧版实现 | `xsystem4`，但版本停在旧 AIN，新指令一堆没文档 |
| 体量足以暴露结构性问题 | 10 章内容、地图 / 战斗 / 编队 / 图鉴 / 存档全都要跑 |
| 用的是同一个引擎的"活"版本 | 版本差异本身就是一个章节（第 3.4 节） |

## 核心命题

> **分清哪些是规范，哪些是实现。**

字节码语义、值的内存布局、函数绑定规则 —— 这些是**规范**，错一个 bit 全盘皆错。
某个 HLL 函数内部的算法、缓存策略、数据结构 —— 这些是**实现**，只要行为兼容，怎么写都行。

搞混这两者，就会在"这个渲染函数为什么不对"上耗掉三天，而真正的问题在"参数占了几个栈槽"。

## 五层结构

全书按依赖关系分五层，**下层错了，上层调不动**：

```
┌──────────────────────────────────────────────┐
│ 5  端到端验证    栈平衡 · 差分对照 · 出画判据  │  ← 判定"真的对了吗"
├──────────────────────────────────────────────┤
│ 4  呈现与输入    编号体系 · 资源格式 · 命中    │  ← 让人看见、能操作
├──────────────────────────────────────────────┤
│ 3  语义库        绑定关系 · 签名 · 版本分派    │  ← 让字节码能调对函数
├──────────────────────────────────────────────┤
│ 2  值表示        ★ 槽宽 · 参数槽数 · 容器类型  │  ← 结构性红线，错了污染全栈
├──────────────────────────────────────────────┤
│ 1  取证          反汇编 · 自证证据 · 交叉验证  │  ← 一切结论的来源
└──────────────────────────────────────────────┘
```

第 2 层是唯一被标红的。它有两个特征：

1. **错了不会报错，只会表现为"别的地方不对"**
2. **一处错会同时污染所有模块**，修一处等于修一片

## 案例总表

全书引用过的兰斯10 真实故障，按章节归类。这张表也是**症状索引**——
你遇到类似现象时，直接跳到对应小节。

### 第 1 章 取证

| 现象 | 根因 | 节 |
|---|---|---|
| 单局 13720 次 `double free` | 三个数组浅拷贝桩裸复制引用元素、不给 `heap_ref` | 1.8 |
| 委托「注册了」却派发不到 | 两端 id 空间不同，只在其中一端打身份 | 1.7 |
| 反汇编从任意偏移开始，指令串全错 | 指令流无自描述，必须从函数头起步 | 1.2 |
| 点卡片不进 `OnClickCard`，连追八轮 | 测试点击落在图鉴卡上；人物卡在 `y=420` 往下，判据采样位置错了 | 1.9 |
| 追两轮「卡池为什么空」，结果它本来就有卡 | 从「B 没被调用」倒推「A 为假」，再倒推「卡池空」——循环论证，没量过一个值 | 1.10 |
| 点编队卡片「怎么都点不中」 | 动作序列写成环境变量，被 `xsys4 seq` 的位置参数覆盖 → 一步没跑（`unknown step`） | 1.11 |
| 定时器报「句柄错误」、场景崩溃，根因却是地图二维网格 | `Array.Alloc` 没建内层数组，`m1[X]=0` 落到全局页，覆写 `global[14]` 单例 | 1.12 |

### 第 2 章 值表示

| 现象 | 根因 | 节 |
|---|---|---|
| `this` 变成堆槽 1（struct #0，3 成员） | `fno=0` 不建帧却仍 `set_struct_page()`；`AIN_WRAP` postset 多算一槽 | 2.2 |
| `CALLMETHOD: invalid function index -1` | `A_REF` 复制接口数组时把 vtable 偏移当对象深拷贝 | 2.4 |
| 同一句柄失效、界面点不动 | 接口元素数组按 1 槽/元素分配，字节码用 `i*2` 索引 | 2.4 |
| 结构体数组元素全是 0 | `Array.Alloc` 不构造元素 | 2.4 |
| 地图装载 RSS 冲 9.5GB → OOM | `Array.Free` 空桩 + `PushBack` 传槽数被当元素数再 ×2 | 2.4 |
| 泛型 `array` 被默认成 int 数组 | 元素类型由**首个元素**定型，声明处没有 | 2.4 |

### 第 3 章 语义库

| 现象 | 根因 | 节 |
|---|---|---|
| `String.GetPart("Tab1", 3)` 时好时坏 | 同名重载（2 参 / 3 参）只按名字绑定，`count` 读到寄存器垃圾 | 3.1 |
| `Tab10` 被当成 `Tab1`，`m_btn[9]` 永不初始化 | 两参 `GetPart` 是"从 Index 截到末尾"，被实现成"取 1 字符" | 3.2 |
| 页签下标 -1 → 空引用 | `GetPart` 差一位（1 基 vs 0 基） | 3.2 |
| 标题菜单点不动 | 用户组件 `数据` 没写回引擎 → `TextButton@Init` 直接 return | 3.9 |
| 提前 return 的分支污染调用者 `this` | no-op 调用不建帧却仍写 `this` | 3.9 |
| 编队点得进去、卡就是加不上 | `Array.Find` 谓词重载没实现，恒返 -1；上层 `if (x != -1)` 全走「没找到」 | 3.10 |
| numeral 一整套 setter「实现了」却毫无效果 | AIN 里真名带 `Parts_` 前缀，`strcmp` 一个都没绑上，全是死条目 | 3.11 |
| 补上 `SetEnableInputProcess` 后编队反而进不去 | 它不是「可点击」；242 次调用里 238 次 `enable=0`，照抄就把按钮全关了 | 3.12 |

### 第 4 章 呈现与输入

| 现象 | 根因 | 节 |
|---|---|---|
| 切场景后标题整层还在 | 图层号被当部件号；遮挡靠"压栈即盖住" | 4.1 |
| 界面点击被容器抢走 | 命中遍历用插入时刻的 z 快照 | 4.4 |
| 点击随机生效 | 帧心跳缺输入阶段；输入窗口未开时消费了按键脉冲 | 4.5 |
| 画面"有部件、无变化" | 帧心跳不推进动画时钟 | 4.3 |
| 汉字显示方框 | 码表对、字体缺简体字形 | 4.6 |
| 开始界面蓝框 + 标签重复 | 按钮是 `TextButton` 内建控件，不是 CG；EX 预览文字层又画一遍 | 4.3 |
| 菜单部件 `show=1` 却一个像素都没有 | 逐个排除 alpha / 状态 / 类型 / controller / 遮挡，五种成因各有判据 | 4.7 |

### 第 5 章 端到端验证

| 现象 | 根因 | 节 |
|---|---|---|
| 委托帧少一格 → `Invalid page index (type=1)` → core | 空引用调用降级只弹不压，调用点后的 `POP` 吃掉调用者一格 | 5.2 |
| 帧被弹歪：`this` 变成另一个对象 | `nargs`（立即数）与 `slots`（按声明算）不相等 | 5.10 |
| 值不对，写端找三轮零命中 | 中间有一次深拷贝，元数据槽被按引用复制成堆槽号 | 5.9 |
| 存档写出去读不回 | 泛型 `array` 三处 switch 缺分支；解析器校验不认 `-1` | 5.8 |
| 指标一条不变 | 改动没打到路径；A/B 开关两侧同值 | 5.3 |
| 编队界面被全屏「新成就」效果盖住 | `Array.Where` 桩忽略谓词，返回整份数组 → "新完成成就"变成"全部成就" | 5.3 |

## 一条诚实的提醒

方法论不能替代耐心。这本书里每一条判据，都是在一次具体的、长达数小时的误判之后写下来的。
它们的价值不在于"让你不犯错"，而在于**让你在犯错后更快地认出自己错了**。

还有一条更刺人的：

> **这本书里一半的错误结论，是我自己写的探针给的。**

限流探针在启动阶段就把配额烧光，然后我据此断定"这个函数没被调用"；
按次数打印的 trace 让多个调用点里只看得见第一个，然后我断定"这里没有注册"。
**探针也是被测对象**——第 5.5 节整节讲这件事。
