# 附录 A 检查清单

## A.1 接手兰斯10 的前三天

### 第一天：能不能跑起来

- [ ] 找到入口：字节码文件、资源包、配置
- [ ] 反汇编器可用（按函数解，不从任意偏移）
- [ ] 能列出所有导入函数的名字
- [ ] 能 dump 字符串表（确认编码）
- [ ] 引擎能启动到"第一个画面出现"或"第一条错误"

**产出**：一份"指令表 / 导入表 / 字符串表"的原始数据。
不要在这一天写任何业务代码。

### 第二天：值表示

- [ ] 确认所有"多槽类型"（接口、包装、可选值）的槽宽与顺序
- [ ] 写 `argument_slots()`，确认参数槽数
- [ ] 确认返回值槽宽的判定方式（声明？调用点标签？）
- [ ] 栈平衡探针上线，跑一次，拿到不平衡函数名单
- [ ] 名单归零（或每条都有解释）

**产出**：这一层不通过，第三天不开始。

### 第三天：语义库 + 呈现

- [ ] 按名绑定全部导入函数，打印未绑定名单
- [ ] 数组/容器库的重载按声明分派
- [ ] 编号体系（组件类型 / 事件码）从游戏自己的表里取
- [ ] 渲染入口每帧被调用
- [ ] 用坐标计算值点击能命中

**产出**：一次"点到目标界面"的完整链路日志。

## A.2 症状速查

按"你观察到的现象"索引，不按层。

| 现象 | 先去查 | 层 |
|---|---|---|
| 赋值目标变成巨大数字 | 栈偏移一格 | 2 |
| 字符串索引非法，值像指针 | 容器类型标错 / 元素没 ref | 2 |
| 强转返回 null 但对象存在 | 接口的 obj 被塞错 | 2 |
| 容器永远为空 | 值的槽宽判错（offset 被当值） | 2 |
| 函数自己没问题，**调用方**局部全乱 | 返回槽宽 | 2 |
| 某个界面就是不显示，其他正常 | 脏标记漏了"场景压栈" | 4 |
| 什么都不显示，但数据都对 | 资源格式版本分叉 | 4 |
| 按钮点不动 | 组件类型号错 → 尺寸为 0 | 4 |
| 点击坐标偏了 | 渲染坐标 vs 窗口坐标 | 4 |
| `Unimplemented function` | 先查它到底有没有被调用 | 3 |
| 返回的字符串是 `0x1` | out-param / 返回值签名错配 | 3 |
| 特定几个函数稳定差 1 个槽 | 指令的版本分派 | 3 |
| 日志全干净 + 全黑 | 正常，这不是通过标准 | 5 |

## A.3 反模式

| 反模式 | 为什么错 | 改成 |
|---|---|---|
| 从任意地址反汇编 | 指令不定长，必然错位 | 从函数入口解 |
| 按名字猜函数语义 | 命名与语义无关 | 按参数/返回形状猜 |
| 照抄开源实现的常量表 | 版本对不上，且不报错 | 从游戏的映射表取 |
| 用崩溃点当 bug 点 | 崩溃是症状终点 | 往上找值是从哪来的 |
| 加兜底让崩溃消失 | 掩盖根因 | 先加断言暴露，修根因 |
| 只测一个函数 | 栈错位要跑完整链才暴露 | 端到端跑一次 |
| 探针默认开启 | 慢十倍、日志爆炸 | 环境变量 + 上限 |
| 按位绑定导入函数 | 版本一变全错 | 按名绑定 |
| 认为"零错误"就是成功 | 零错误 + 全黑很常见 | 三个判据 |
| 实现了没人调用的函数 | 浪费，且会增加误判面 | 先查调用次数 |

## A.4 一个健康的项目长什么样

不是"没有 bug"，而是这几条能随时回答：

1. 现在卡在哪一层？（1/2/3/4/5）
2. 卡点的**可证伪判据**是什么？
3. 上一个结论的证据是什么，有几条？
4. 有哪几个常驻诊断，各自解决什么问题？
5. 哪些债是"冻结"的，冻结理由是什么？

如果第 1 条答不上来，说明还在凭感觉改代码。

## A.5 术语

| 词 | 含义 |
|---|---|
| **槽 (slot)** | 操作数栈/局部变量页里的一格，通常 4 或 8 字节 |
| **槽宽** | 一个"值"占几格 |
| **页 (page)** | 引擎里的对象容器：全局页、局部页、结构页、数组页、委托页、接口页 |
| **HLL** | 宿主语言实现的函数，供字节码调用 |
| **泛型返回** | 同一个导入函数按调用点标签返回不同类型 |
| **自证证据** | 程序为自身使用而维护的映射表/校验，不会说谎 |
| **差分对照** | 单变量改动 + 两次运行 + 只比一个指标 |
| **冻结债** | 已知不完美但明确不处理的问题，有记录、有理由 |
| **出画判据** | 截图文件大小 + 灰度均值，可量化的"有内容" |

## A.6 最后一句

这套方法论没有一条是"聪明"的。它们全都是**在被同一个问题骗过之后**总结出来的。

所以它真正的作用不是让你少走弯路，而是让你在走弯路时**更快地意识到自己在走弯路** ——
这已经能省掉大部分时间了。
