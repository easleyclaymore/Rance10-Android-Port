# dev/patches/ —— 历史补丁脚本（只读参照）

这些是一次性用来改源码的 Python 脚本，**改动早已落到 `src/` 里**，
保留是因为它们记录了"当时怎么改的"，有取证价值，不是可重放的工具。

## 状态

| 文件 | 状态 |
|---|---|
| `d110*_patch.py` | 已应用（D110 系列），**不要重跑** |
| `libsys4-gsave-v8.patch` | 上游 libsys4 的补丁，供参照 |

## 两个坑

**一、路径写死在原作者机器上。** 例如 `d110_patch.py` 第 5 行：

```python
PATH = "/home/alin/Rance10_Port/xsystem4/src/ffi.c"
```

那是另一台机器（`alin`）的绝对路径。直接跑会找不到文件；
就算存在，也会对着**已经改过多次**的源码重复打补丁。

**二、它们不是幂等的。** 脚本按"找到某段原文就替换"来工作，
源码一旦变化就不再匹配，可能静默什么都不做，也可能改坏。

## 如果需要重放某一项

不要直接跑这些脚本。正确做法是：

1. 用 `git log` 找到对应的提交（`D110` 在提交信息里）
2. `git show <sha> -- <文件>` 看当时的真实 diff
3. 需要的话手工 `git revert` 或 `git cherry-pick`

## 判据

保留 + 标注 > 删除。这些脚本能回答"某个奇怪的写法是谁、为什么加进来的"，
但必须明确标成**只读历史**，否则下一个人会以为它们能跑。
